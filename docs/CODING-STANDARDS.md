# Coding Standards

## TypeScript and React

- Use functional React components and strict TypeScript.
- Define explicit types for shared data and component contracts.
- Avoid `any`; prefer narrow unions, interfaces, and inference.
- Keep components and hooks focused on one responsibility.
- Extract reusable logic when it genuinely reduces duplication.
- Keep state as close as practical to the UI that owns it.

## UI and accessibility

- Use semantic HTML, accessible names, keyboard-operable controls, and visible focus.
- Keep responsive behavior and dark/light theme presentation consistent.
- Respect reduced-motion preferences and use animation only when it serves the experience.
- Preserve the portfolio’s established typography, spacing, and restrained color palette.

## General

- Follow nearby naming and formatting conventions.
- Prefer simple, readable code over speculative abstractions.
- Do not add dependencies without a concrete need and a review of their impact.
- Update documentation when behavior, architecture, setup, or configuration changes.
